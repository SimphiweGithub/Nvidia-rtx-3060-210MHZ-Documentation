## Meaning and limits

The DriverStore NVML implementation contains D3DKMT references and a normal static import of `DeviceIoControl`. Both are compatible with possible user-mode-to-driver transport routes, but neither proves that `nvmlDeviceGetPowerUsage` uses the route. Determining that requires a call graph from the captured handler or a narrowly scoped trace at a call site reached from that handler.

The full artifact is [`nvml-power-usage-call-map-2026-09-02.txt`](nvml-power-usage-call-map-2026-09-02.txt).

This is a narrowing result only. The mapper intentionally omits dynamically resolved calls, register-indirect calls, and unrecognized instruction forms, and it does not demonstrate execution. The focused one-query debugger capture remains necessary to determine the actual transport.
